What the spec leaves open

  • Discount and eligibility. The $18 discount is illustrative. Product prices, USD, and shipping are fixtures, not promotion rules.
  • Failure routing. This preview sends service failures to recovery and keeps rejected codes in checkout. AC8 needs clarification.
  • Multiple codes. Reapplying the same code is safe. Combining or replacing different codes is not simulated because the behavior is undefined.
  • UI details. Layout, copy, and the empty-field message are illustrative. Checkout is reduced to the promo-code flow.

AC1

Code entry. Checkout provides a labeled promo-code field and an action to apply it.

Checkout field and Apply code.

AC2

Valid code. Applying a valid code to an eligible cart immediately updates the visible discount and total.

AC3

Expired or invalid code. Reject expired or invalid codes with an informative error. Do not apply a discount, and keep totals accurate.

Expired-code error, or show the invalid-code error. Totals stay unchanged.

AC4

Ineligible cart. Do not apply a discount when the cart is ineligible. Explain the outcome to the customer.

Ineligible-cart error. No discount is applied.

AC5

One-time use. A redeemed one-time code cannot be reused. Show an informative error when it is rejected.

Rejection message for a redeemed one-time code.

AC6

Discount visibility. Show the applied discount in both the checkout summary and the final order confirmation.

Discount in checkout, or show the final confirmation.

Duplicate prevention. Applying the same code again must not apply its discount twice or change the total again.

Service failure opens recovery; destination is an assumption.
